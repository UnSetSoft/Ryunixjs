# Ryunix Webpack Preset

The `@unsetsoft/ryunix-presets` package configures Webpack for an optimal Ryunix full-stack application experience.

## Dual Compiler Architecture

If Server-Side Rendering (SSR) is enabled via `ryunix.config.js`, or if static pre-rendering is required, the preset uses Webpack's multi-compiler mode to build both Client and Server targets simultaneously.

- **Client `clientConfig`**: Emits the standard bundles to the `/static` folder. Leverages `TerserPlugin` and `CssMinimizerPlugin` for minification. Hot Module Replacement (HMR) is active via `webpack-dev-server`.
- **Server `serverConfig`**: Compiles for Node.js (`target: 'node'`) using `experiments.outputModule: true` to generate native ES Modules. Ignores CSS file generation and outputs the routing entry point required for SSR handling.

## Custom Webpack Plugins

### `AppRouterPlugin`
Responsible for analyzing the `/app` directory structure and generating a unified routing mapping file.

### `ApiRouterPlugin`
Similar to the App Router Plugin, but focuses on the backend API endpoints. It maps structures within the `/app/api` directory to server request handlers.

### `RyunixRoutesPlugin`
Handles SSG (Static Site Generation). It executes pre-rendering logic to output HTML snapshots (`routes.json`) of specified paths during the build process.

## Dev Server Middlewares

The Webpack Dev Server provides `setupMiddlewares` to seamlessly integrate SSR and API requests during development:

1. **Server Actions (`/_ryunix/action`)**: Captures `POST` requests and executes globally registered async handlers.
2. **API Routes**: Pipes requests through `handleApiRequest` corresponding to the files generated by `ApiRouterPlugin`.
3. **SSR Render (`renderDevRoute`)**: Intercepts `GET` requests for HTML. Uses the compiled Server Bundle to render the DOM to a string/stream (using `renderToReadableStream` on `Ryunix`), injects local CSS modules, and dynamically serves it to the browser preventing FOUC (Flash of Unstyled Content).
